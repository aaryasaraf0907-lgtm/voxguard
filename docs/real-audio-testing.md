# Real-audio sanity check

`scripts/real_audio_sanity.py` scores a few consented, labelled recordings through the public
API and writes a private report. It is a **diagnostic**: it shows how the deployed model treats
real microphones and recorders, for example false alarms on genuine speech near the threshold.
A handful of clips supports **no accuracy, FAR, FRR or EER claim**. Measured results belong in
`docs/results.md`, which is generated by `evaluate.py`.

Agreed with Aarya on 16 Nov:
- it uses the public API only (`GET /health`, `POST /v1/analyze`);
- it uses no detector internals and gives no per-window output;
- ground truth, source and consent are given explicitly for every file and are never inferred
  from predictions.

## Data rules

- **Consented recordings only.** Every person recorded agreed to it, or the clip is synthetic
  or openly licensed. Never use third-party recordings (for example, clips taken from websites).
- **Keep everything private and outside the repository.** The tool refuses an audio folder,
  labels file, report folder or scratch database inside any git working tree.
- **Never commit audio, labels, reports or scratch databases.** Results are shared privately.
- **Write `source` neutrally**, for example "speaker A, laptop mic". Leave out names and other
  personal details the check doesn't need.
- **Excluded by default:** `voxguard_test.wav`. The tool refuses it unless it is named with
  `--allow-file`.

## Labels file

A CSV with one row per file.

| Column | Required | Values |
|---|---|---|
| `file` | yes | path relative to the audio folder |
| `ground_truth` | yes | `genuine` or `spoof` |
| `source` | yes | how the clip was made |
| `consent` | yes | must be `yes` |
| `notes` | no | free text, copied to the report |

```csv
file,ground_truth,source,consent,notes
mic-01.wav,genuine,speaker A laptop mic,yes,quiet room
tts-01.wav,spoof,open TTS model,yes,
```

The run stops before sending anything, including `/health`, if any of the following is true:
- any row lacks `consent=yes`;
- a `ground_truth` value is unknown;
- a `source` is empty;
- a file is listed twice;
- a file is missing;
- a path leaves the audio folder (absolute, `..`, or a symlink pointing outside);
- a file is larger than 100 MB (the tool's own read limit; the API's 25 MB limit still
  applies, and gives a 413);
- a `--codec` value is not a plain codec name;
- an excluded file is listed;
- the API URL is unsafe;
- a folder is inside a git working tree.

Files in the audio folder without a row are listed as unlabelled and never sent.

## 1. Start a scratch API

The API stores a session for every analysed upload, and an alert for every flagged one. So the
check runs against its own API and a new database, never the demo compose stack or its
`voxguard-data` volume:

```bash
VOXGUARD_MODEL_REPO=voxguard-team/voxguard-ssl-aasist-codec-aug \
  make sanity-api SANITY_DB=$HOME/voxguard-private/sanity-2026-11-17.db
```

`serve` starts uvicorn on `127.0.0.1:8100` with the real detector. It fails closed: nothing
starts if the database file already exists (or its SQLite side files do), or if the database:
- is called `voxguard.db` (the demo and default name);
- is under `/data` or a Docker volume;
- has no existing parent folder;
- is inside a git working tree.

It also refuses the demo ports (8000, 8501) and any address that isn't loopback. It loads the
checkpoint from the local Hugging Face cache with downloads off (`--online` allows them), and
needs the `api` and `ml` extras. Delete the scratch database when you are done.

## 2. Run the check

In another terminal:

```bash
make sanity SANITY_URL=http://127.0.0.1:8100 \
  LABELS=$HOME/voxguard-private/labels.csv AUDIO=$HOME/voxguard-private/clips \
  OUT=$HOME/voxguard-private/reports
```

Extra options go in `SANITY_ARGS`:

| Option | Effect |
|---|---|
| `--codec g711_mulaw` | also score every file through that phone-line codec; can be repeated; off by default |
| `--expect-model-version …` | stop if `/health` reports a different model |
| `--allow-stub` | accept the stub detector (tests only; its scores are placeholders) |
| `--allow-file NAME` | include a file that is excluded by default |
| `--allow-remote` | allow an API that isn't on this machine |
| `--timeout S` | per-upload timeout; default 300 s |

## How a run behaves

- **Order:** `/health` first. The run refuses the stub detector, and stops on a
  `--expect-model-version` mismatch. Then one `POST /v1/analyze` per file and condition. No
  caller ID is sent, so the blocklist isn't touched.
- **Responses** are checked against the API schema and recorded exactly as returned. The API's
  label is stored as `predicted_label`, apart from the CSV's `ground_truth`.
- **Error statuses** (413, 415, 422, 500, 503) are recorded with the server's message, and the
  run continues. Limits are never bypassed, and long clips are not split.
- **Malformed or schema-invalid responses** are recorded as `invalid_response`; a session was
  probably stored.
- **Uploads are never retried.** After a timeout the session may or may not exist, so the
  outcome is `unknown`. After a refused connection nothing was stored (`not_sent`). Either way
  the run stops, and the remaining files are marked `not_sent`.
- **Score ÷ threshold** is reported as `n/a` when the threshold is 0 or not a finite number.
  "Near threshold" uses the UI's rule: `threshold <= score < 1.5 × threshold`.
- **Exit code:** 0 when every request was answered and every response named the `/health`
  model; 1 otherwise; 2 when validation refused the run.

## Reports

Each run writes `sanity-<UTC time>.json` and `sanity-<UTC time>.md` to `--out`. Existing reports
are never overwritten.
- **Run details:** API URL, `/health`, the tool's git commit, the labels file's name and SHA-256.
- **Per file:** the file name relative to the audio folder, SHA-256, size, outcome and the
  response as returned.
- **Counts per condition and ground truth:** listed, scored, flagged, not flagged, near the
  threshold, not scored. Counts, never rates.
- **The caveats,** including that model identity is only what the public API reports (no
  checkpoint SHA-256 or Hugging Face revision).
- **Never included:** audio, absolute paths or tokens.
